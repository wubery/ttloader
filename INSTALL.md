# Video Poster — установка, запуск и эксплуатация

Панель автопостинга видео в **TikTok** и **YouTube Shorts**: своя авторизация,
личный прокси на аккаунт, вжигание баннеров и текста в видео, уникализация,
Telegram-бот, обновление одной кнопкой. Всё работает в Docker.

## 1. Что нужно на сервере

- Linux (проверено на Ubuntu 20.04/22.04), **root или sudo** (нужен один раз — для автозапуска).
- **Docker** + плагин **docker compose v2**, **git**, **curl**.
- ~6 ГБ свободного места (образ Playwright с Chromium ≈ 2 ГБ) и ~2 ГБ RAM.
- Свободный порт панели (по умолчанию **8088**).

Проверка:

```bash
docker --version && docker compose version && git --version
```

Если пользователь не в группе `docker`, добавьте (и перезайдите в сессию):

```bash
sudo usermod -aG docker $USER
```

## 2. Быстрая установка из git (рекомендуется)

Именно этот способ даёт работающую кнопку **«Обновить с GitHub»**.

```bash
git clone https://github.com/wubery/ttloader.git video-poster
cd video-poster
bash install.sh
```

Установщик соберёт контейнеры, создаст `.env`, поставит автозапуск апдейтера и
**один раз** покажет логин с паролем:

```
Панель:  http://<IP-сервера>:8088
Логин:   admin
Пароль:  <случайный пароль>
```

Первая сборка — 5–10 минут (тянется образ Playwright и Chromium). Дальше панель
поднимается сама при перезагрузке сервера (`restart: unless-stopped`).

Если `install.sh` запущен **без** root, автозапуск апдейтера не установится —
он сообщит об этом. Поставить вручную:

```bash
sudo tee /etc/systemd/system/vp-updater.service >/dev/null <<EOF
[Unit]
Description=Video Poster updater
After=docker.service
Requires=docker.service

[Service]
Type=simple
User=$(id -un)
Group=$(id -gn)
WorkingDirectory=$(pwd)
ExecStart=/usr/bin/env bash $(pwd)/updater.sh
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now vp-updater
```

> Апдейтер работает **на хосте**, а не в контейнере: панель лишь кладёт флаг в
> каталог `update/`, поэтому контейнеру не нужен доступ к docker.

## 3. Установка из архива (zip)

```bash
unzip video-poster-v2.zip      # появится папка video-poster/
cd video-poster
bash install.sh
```

Всё то же самое, но кнопка «Обновить с GitHub» работать **не будет** (нужен
git-клон — см. п. 2). В архиве **нет секретов**: токен бота, chat_id и прокси
задаёте сами.

## 4. Установка из приватного репозитория

Пароль GitHub для git не подходит — нужен **токен**.

1. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate new token:
   доступ **только к этому репозиторию**, право **Contents: Read-only**.
2. Установка с токеном:

```bash
git clone https://<ТОКЕН>@github.com/wubery/ttloader.git video-poster
cd video-poster
VP_GIT_TOKEN=<ТОКЕН> bash install.sh
```

Токен уйдёт в `.git-credentials` (права 600, в `.gitignore`), из `remote`-URL он
вычищается, чтобы не светился в логах и в `git remote -v`.

Токен можно не задавать при установке, а вписать позже в панели:
**«Настройки» → «Обновление» → «Токен для приватного репозитория»**. Он **не
хранится в базе**: панель передаёт его апдейтеру файлом с правами 600, тот
переносит токен в git credential store и файл удаляет. Рядом с кнопкой видно
состояние доступа: «доступ к репозиторию есть» / «нужен токен GitHub» /
«установлено не из git».

Доступ коллеге: GitHub → Settings → **Collaborators** → Add people (роль Write
или Read). Раздел «Contributors» руками не меняется — он строится из истории
коммитов.

Альтернатива токену — **deploy key**: `ssh-keygen -t ed25519` на сервере,
публичный ключ в Settings → **Deploy keys** (read-only), затем
`git remote set-url origin git@github.com:wubery/ttloader.git`.

## 5. Параметры установки

```bash
VP_PORT=9000 bash install.sh           # другой порт панели
VP_USER=boss bash install.sh           # другой логин
VP_PASS='МойПароль' bash install.sh    # свой пароль вместо случайного
VP_REGEN=1 bash install.sh             # пересоздать .env с новыми логином/паролем
VP_GIT_TOKEN=ghp_... bash install.sh   # токен для приватного репозитория
```

Настройки рендера правятся там же — в `.env` рядом с сервисом `backend`
(`docker compose up -d` после правки):

```bash
VIDEO_CRF_MIN=18        # качество: меньше — лучше картинка и больше файл
VIDEO_CRF_MAX=20
VIDEO_PRESET=veryfast   # medium — качественнее, рендер примерно втрое дольше
AUDIO_BITRATE=192k
UNIQ_FORCE_NOISE=0      # 1 вернёт принудительный шум в пути без профиля
OUTPUT_KEEP_DAYS=14     # сколько дней хранить скриншоты и старые рендеры
```

Всё это попадает в `.env` (в git не уходит) и применяется **при первом запуске**;
дальше пароль меняется в самой панели → «Настройки». `VP_REGEN=1` перезапишет
`.env`, но пароль уже созданного администратора в базе не изменит — для смены
пароля пользуйтесь панелью.

## 6. Первый вход в панель

1. Откройте `http://<IP-сервера>:8088` — появится страница входа.
2. Логин и пароль — те, что показал установщик.
3. Смените пароль: «Настройки» → «Смена пароля».

Панель закрыта на уровне приложения: любой `/api/*` без сессии отдаёт **401**
(кроме `/api/auth/*` и `/api/health`). Сессия — подписанная httponly-cookie.

Проверка здоровья: `http://<IP>:8088/api/health` — покажет доступность ffmpeg и
Playwright.

## 7. Telegram: уведомления, бот, вход по коду

1. Создайте бота у **@BotFather**, получите токен.
2. Узнайте свой **chat_id** (например, у @userinfobot) и **напишите боту** `/start` —
   иначе бот не имеет права писать вам первым.
3. В панели → «Настройки» → Telegram: вставьте токен и chat_id. **Можно несколько
   через запятую**: `598116316, 500135254` — уведомления и код входа получат все,
   и командовать ботом могут все указанные.
4. Галочка «Разрешить вход в панель через Telegram» включает вход по коду:
   на странице входа появится кнопка, код придёт в чат (действует 5 минут).

Что делает бот: уведомляет о публикации и об упавших прокси; команды
`/queue`, `/accounts`, `/videos`, `/stats`, `/status`, `/proxy`, `/newpost`,
`/delete`, `/settings`; присланное боту **видео** попадает в библиотеку, **фото** —
в баннеры.

## 8. Если Telegram заблокирован у провайдера (туннель)

Через туннель идёт **только трафик бота**, остальное — напрямую.

```bash
cp xray/config.example.json xray/config.json
nano xray/config.json          # впишите свой VLESS: адрес, порт, uuid
echo 'COMPOSE_FILE=docker-compose.yml:docker-compose.xray.yml' >> .env
docker compose up -d --build
```

Строка `COMPOSE_FILE` в `.env` важна: без неё обычные команды `docker compose`
и пересборка при обновлении поднимут стек **без** туннеля, и бот замолчит.
`install.sh` добавляет её сам, если `xray/config.json` уже существует;
апдейтер тоже подхватывает override при наличии этого файла.

Backend получит `TELEGRAM_PROXY=http://xray:10809` автоматически. Проверить:

```bash
docker compose exec backend printenv TELEGRAM_PROXY
docker compose logs --tail 20 xray
```

`xray/config.json` в git не попадает (там ваш uuid).

## 8а. Автоматический вход в аккаунты (логин, пароль и код из почты)

Панель умеет входить в аккаунт сама: вводит логин с паролем через прокси аккаунта,
достаёт код подтверждения из почты и сохраняет куки. Руки нужны только при капче.

### Что заполнить в профиле

При создании аккаунта (вкладка «Аккаунты») кроме названия и прокси укажите:
**логин TikTok**, **пароль**, **почту аккаунта** и **пароль от почты**. Пароли
хранятся зашифрованными (Fernet, ключ в `VP_SECRET_KEY` или в `/data/secret.key`)
и наружу из панели не отдаются. Галочка «войти сразу» запускает вход сразу после
создания профиля.

### Подключение почты Microsoft (outlook, hotmail, live)

Обычный пароль к почте для чтения писем **больше не подходит**: Microsoft отключила
basic-аутентификацию для IMAP в личных ящиках, теперь нужен OAuth. Поэтому ящик
подключается один раз, кодом.

**Разово, один раз на всю панель** — зарегистрируйте бесплатное приложение:

1. [portal.azure.com](https://portal.azure.com) → **App registrations** → **New registration**.
2. Имя — любое; **Supported account types** → *Personal Microsoft accounts only*;
   Redirect URI **не указывайте**.
3. В созданном приложении: **Authentication** → включите **Allow public client flows: Yes** → Save.
4. **API permissions** → Add a permission → **Microsoft Graph** → *Delegated* →
   отметьте **Mail.Read** и **offline_access** → Add.
5. Скопируйте **Application (client) ID** и вставьте в панели:
   «Настройки» → «Почта аккаунтов» → Client ID → Сохранить.

**Дальше на каждый ящик:** у профиля кнопка **«Подключить почту»** → панель покажет
код → откройте [microsoft.com/devicelogin](https://microsoft.com/devicelogin), введите
код и войдите в этот ящик. Пароль вводится на странице Microsoft, а не в панели.
После этого панель читает письма сама.

### Почта других провайдеров

Если ящик не Microsoft (например, firstmail), панель работает по обычному IMAP:
достаточно адреса и пароля, сервер подставляется по домену автоматически (можно
задать вручную). Для Gmail/Яндекс/Mail.ru понадобится «пароль приложения» из
настроек соответствующей почты.

### Что происходит при входе

Панель показывает стадии: *Готовлю браузер → Ввожу логин и пароль → Жду письмо с
кодом → Ввожу код → Готово*. Если письмо не подхватилось, в том же окне можно ввести
код руками или нажать «взять код из почты». Если TikTok показал капчу, панель
покажет скриншот и остановится: решите её в антидетект-браузере через тот же прокси
и импортируйте куки.

### Автоперелогин

Куки TikTok со временем протухают. Панель проверяет их живость по расписанию (раз в
6 часов, параметр `session_check_hours`) и перед публикацией: если сессия умерла, а
логин с паролем есть — входит заново и продолжает задачу. Отключается галочкой
`auto_login` у аккаунта.

**Честные оговорки.** Вход по паролю — именно то, что ловит антибот TikTok: с
датацентровых прокси капча появляется часто, и часть входов всё равно потребует рук.
Хранение логинов и паролей в панели концентрирует риск: доступ к панели = доступ к
аккаунтам. И автоматизация входа противоречит правилам TikTok — аккаунт могут
заблокировать.

## 9. Аккаунты, прокси, куки

1. «Аккаунты» → создать: имя, платформа, **прокси** в виде
   `http://логин:пароль@хост:порт`. У каждого аккаунта — **свой** прокси
   (панель не даст назначить один прокси двум аккаунтам).
2. «Проверить IP» показывает реальный egress-IP прокси. Прокси проверяются и по
   расписанию, о падении приходит уведомление в Telegram.
3. Куки — два пути:
   - **Вход из панели**: логин/пароль → код с почты вводится в панели → куки
     сохраняются. При капче панель покажет скриншот.
   - **Импорт кук** (надёжный вариант): войдите в браузере через **тот же
     прокси**, снимите куки расширением (например, Cookie-Editor) и загрузите
     JSON в карточку аккаунта.

### Группы аккаунтов

Аккаунты можно разложить по **группам-когортам** — чтобы проверять гипотезы
постинга («прогретые против новых», «с хуком против без»):

1. «Аккаунты» → карточка **«Группы аккаунтов»** → задать имя и цвет.
2. В карточке аккаунта выбрать группу в выпадающем списке (аккаунт входит ровно
   в одну группу; «группа: не задана» — снять привязку).
3. «Новый пост» → выпадающий список групп над списком аккаунтов: выбор группы
   отмечает все её пригодные аккаунты, лишние можно снять галочкой. Тот же список
   есть в окне публикации из «Баннер+превью».
4. «Статистика» → таблица **«По группам»**: задачи, выполнено, ошибки и процент
   успеха по каждой когорте.

Нюансы:

- На рендер, уникализацию и постинг группа **не влияет** — только на выбор
  аккаунтов и на разбивку статистики.
- Статистика считается по **текущей** принадлежности: переносите аккаунт в другую
  группу — его прошлые посты уезжают вместе с ним.
- Удаление группы аккаунты не трогает, они просто теряют привязку.
- Telegram-бот групп не знает и по-прежнему постит на все активные аккаунты.

### Папки: какие видео, хуки и фоны достаются какой группе

Папки есть у трёх библиотек — «Видео», «Хуки» и «Фоны». Папки каждой библиотеки
свои, а на папку вешаются группы аккаунтов:

1. На вкладке библиотеки — кнопка **«Папки»**: создать, переименовать, отметить
   группы, удалить.
2. У каждого файла — выпадающий список папки.
3. Полоска чипов над списком фильтрует библиотеку: «Все», папки, «Без папки».

Правило доступа простое:

- файл **без папки** доступен всем группам;
- папка, на которой **не отмечено ни одной группы**, тоже ничего не ограничивает —
  это просто полка;
- как только на папке отмечены группы, её содержимое достаётся **только им**.

Работает в двух местах: в «Новом посте» список видео сужается до доступных
выбранной группе (галочка «показать все» снимает сужение), а при рендере
случайный выбор хука и фона идёт уже с этим фильтром — по группе того аккаунта,
на который публикуется задача. Аккаунт без группы не ограничен ничем. У рекламы
и оверлеев папок нет, они берутся из всей библиотеки; конкретный файл, выбранный
в профиле вручную, тоже берётся как есть.

Важные нюансы:

- **SOCKS5 с логином/паролем Chromium не поддерживает** — используйте `http://`-прокси.
- Сессия TikTok привязана к IP: куки, снятые под одним IP, на другом IP
  разлогинятся. Прокси аккаунта после импорта кук менять нельзя.
- Датацентровые IP (обычные VPS) TikTok часто не пускает на вход — для аккаунтов
  лучше мобильные/резидентские прокси.

## 10. Видео, баннеры, слои и публикация

Размер заливаемого файла панель не ограничивает (`client_max_body_size 0` в
nginx), таймауты подняты до 10 минут. Ограничением остаётся место на диске
сервера и терпение: прогресс заливки в панели не показывается, большой файл
просто какое-то время висит на надписи «Загрузка...».

1. «Видео» → загрузить ролики (целый mp4; обрезанный файл без moov-атома
   ffmpeg и TikTok не примут).
2. «Баннеры» → загрузить PNG (с прозрачностью) или **зацикленное видео**.
3. «Баннер+превью» → выбрать видео, добавить слои:
   - **баннеры** (несколько), перетаскивание и масштаб мышью, прозрачность,
     движение по кадру (drift/bounce/slide);
   - **текст** — размер, цвет, прозрачность, положение;
   - у каждого слоя можно задать **время показа** (с… по…).
4. Кнопка **«Опубликовать»** → аккаунт, подпись, время → задача в очередь.
   Все слои **вжигаются** в видео через ffmpeg.
5. «Уникализация» у аккаунта меняет хеш видео (микро-кроп, шум, метаданные, CRF),
   чтобы одинаковые ролики не склеивались антифродом.
6. «Очередь» → статусы `ожидает → рендер → постинг → готово`, логи, повтор при ошибке.

### Уникализация видео (вкладка «Уникализация»)

Панель может прогнать ролик через конвейер, который меняет его так, чтобы копии
для разных аккаунтов не были одинаковыми:

1. обрезка по длине (срезает часть с начала/конца);
2. изменение скорости — видео и звук синхронно;
3. кроп по краям;
4. поворот на 1–3° с компенсацией масштаба (чёрных углов не будет) либо переворот
   на 180° — он включается только вручную, зритель его заметит;
5. цветокоррекция из пресетов (тёплый, холодный, контраст, выцветший, сочный);
6. микро-шум;
7. вписка в холст 1080×1920 с рамкой: фон — сплошной цвет или размытая копия кадра;
8. полнокадровый PNG-оверлей из библиотеки оверлеев;
9. склейка с **хуком** — короткой заставкой из библиотеки хуков, которая проходит
   те же операции со своими значениями;
10. снятие метаданных и кодирование.

Всё это — **один проход ffmpeg**; слои редактора (баннеры и текст) накладываются
в том же проходе.

**Профили.** Настройки живут в профилях: каждый параметр задаётся диапазоном «от–до».
Панель берёт случайное значение из диапазона **на каждый рендер** — поэтому у
каждого аккаунта получается своя копия. Кнопка «=» рядом с диапазоном фиксирует
значение: это и есть ручной режим. Кнопки «Мягкий / Средний / Агрессивный»
заполняют диапазоны готовыми наборами.

Профиль выбирается при создании поста и в редакторе, закрепляется за аккаунтом
(селект в карточке аккаунта) или помечается «по умолчанию» — тогда он применяется
ко всем задачам, где ничего не выбрано. Если профилей нет, работает прежнее
поведение по галочке «уникализация» у аккаунта.

**Предпросмотр** рендерит три секунды с текущими настройками — иначе параметры
подбираются вслепую.

**Качество кодирования.** Ролик пережимается один раз: `libx264`, CRF из диапазона
`VIDEO_CRF_MIN`–`VIDEO_CRF_MAX` (по умолчанию 18–20; чем меньше, тем лучше картинка
и больше файл), пресет `VIDEO_PRESET` (по умолчанию `veryfast`; `medium` даёт чуть
лучше при примерно втрое большем времени рендера), звук `AUDIO_BITRATE` (192k).
Случайный CRF — тоже часть уникализации: другой битрейт даёт другой хеш.

Шум **не** подмешивается принудительно. Раньше в пути без профиля он добавлялся
всегда и сильнее всего портил картинку — кодек тратил битрейт на зерно, ролик
выглядел «зашакаленным». Хеш меняют и микрокроп с ресайзом, цветокоррекция и
случайные метаданные. Вернуть прежнее поведение можно через `UNIQ_FORCE_NOISE=1`,
а в профилях шум остаётся отдельной настройкой с диапазоном силы.

Оговорка: конвейер меняет байты и картинку, но TikTok по-прежнему видит тот же
сюжет и ту же звуковую дорожку. Обрезка и скорость к тому же реально меняют ролик
(минус до 10% длительности, сдвиг тона голоса), поэтому агрессивные значения по
умолчанию не выставлены.

### Постинг на несколько аккаунтов сразу

В «Новом посте» и в кнопке «Опубликовать» аккаунты выбираются **чекбоксами**
(есть «Выбрать все»). На каждый аккаунт создаётся **отдельная задача со своим
рендером** — то есть у каждого свой файл и свой хеш; общий отрендеренный файл не
переиспользуется намеренно.

Когда выбрано больше одного аккаунта, появляется блок настроек пачки:

- **пауза между аккаунтами** (по умолчанию 5–20 минут): первый пост уходит сразу,
  каждый следующий — через случайный интервал из этого диапазона;
- **варьировать подпись** — панель переставляет хештеги и добавляет эмодзи в конец,
  чтобы подписи не были байт-в-байт одинаковыми. Тело текста не меняется.

В очереди задачи одной пачки помечены бейджем «группа · N из M», а в Telegram
вместо N сообщений приходит одно итоговое («опубликовано 4 из 5»); об ошибках
отдельных задач бот сообщает сразу.

Через бота: `/newpost 1,2,5 3 подпись` или `/newpost all 3 подпись` (все активные
аккаунты с куками).

Важно: разный хеш не отменяет того, что TikTok видит один и тот же ролик на
нескольких аккаунтах (аудио-отпечаток, картинка). Разброс по времени и вариации
подписи снижают заметность, но гарантий не дают — и у каждого аккаунта обязательно
должен быть **свой прокси**.

Селекторы TikTok/YouTube меняются: они вынесены в начало
`backend/app/services/uploaders/tiktok.py` и `youtube.py` — если постинг
сломался, правьте там.

## 11. Обновление панели

**Из панели:** «Настройки» → «Обновление» → **«Обновить с GitHub»**. Хостовый
апдейтер сделает `git pull` + пересборку и, если обновился сам, перезапустится.
Статус («Обновление: git pull…» → «Пересборка контейнеров…» → «Обновлено
успешно (хеш)») виден там же. Работает только для установки **из git**.

**Вручную:**

```bash
cd video-poster
git pull && docker compose up -d --build
```

Если обновление ругается «Your local changes would be overwritten» — в каталоге
есть правки руками; отмените их (`git checkout -- .`) или сохраните
(`git stash`). Данные при обновлении не теряются — они в docker-томе.

## 12. Управление контейнерами

```bash
cd video-poster
docker compose ps                    # состояние
docker compose logs -f backend       # логи бэкенда
docker compose logs --tail 50 xray   # логи туннеля
docker compose restart backend       # перезапуск
docker compose down                  # остановить (данные остаются)
docker compose up -d                 # поднять снова
systemctl status vp-updater          # апдейтер
journalctl -u vp-updater -n 50       # его журнал
sudo systemctl restart vp-updater    # перезапуск апдейтера
```

## 13. Бэкап и восстановление

Всё ценное (аккаунты, куки, видео, баннеры, БД) — в docker-томе `vp_data`.

**Бэкап:**

```bash
mkdir -p ~/backups
docker run --rm -v video-poster_vp_data:/d -v ~/backups:/b alpine \
  tar czf /b/vp_data-$(date +%F).tgz -C /d .
```

Имя тома = `<имя_каталога>_vp_data` (проверить: `docker volume ls`).
Отдельно сохраните `.env` (логин/пароль) и `xray/config.json`.

**Восстановление:**

```bash
cd video-poster && docker compose down
docker run --rm -v video-poster_vp_data:/d -v ~/backups:/b alpine \
  sh -c "rm -rf /d/* && tar xzf /b/vp_data-2026-07-25.tgz -C /d"
docker compose up -d
```

## 14. Несколько экземпляров на одном сервере

Имя compose-проекта берётся из имени каталога, поэтому **два каталога с
одинаковым именем — это один проект** (второй запуск «переедет» на первый и
затрёт его). Для тестового экземпляра рядом с рабочим задавайте имя и порт явно:

```bash
COMPOSE_PROJECT_NAME=vp2 VP_PORT=8091 docker compose up -d --build
```

У него будет свой том `vp2_vp_data` и свои данные.

## 15. Диагностика типовых проблем

| Симптом | Причина и что делать |
|---|---|
| `502 Bad Gateway` сразу после обновления | Бэкенд ещё поднимается, подождите 20–40 с. |
| Панель просит вход, а пароль не подходит | Пароль в базе; сбросить — `VP_REGEN=1` не поможет. Заведите новый пароль через «Настройки» под старым или удалите строку настроек в БД. |
| Кнопка «Обновить» пишет «установлено не из git» | Каталог не git-клон — переустановите по п. 2 (данные в томе сохранятся). |
| «Нет доступа к репозиторию (приватный?)» | Вставьте токен GitHub в «Настройках» (п. 4). |
| «Ошибка git pull: … local changes» | В каталоге правки руками: `git checkout -- .` |
| Статус обновления «замер» на одной фразе | Апдейтер не может писать в `update/` — `docker compose exec -T backend chown -R $(id -u):$(id -g) /update`, затем `sudo systemctl restart vp-updater`. |
| Код входа в Telegram не приходит | Напишите боту `/start`; проверьте токен и chat_id; если `api.telegram.org` заблокирован — поднимите туннель (п. 8). |
| «Код не отправлен: бот не смог связаться с Telegram» | Именно сетевая проблема: смотрите `docker compose logs --tail 30 backend` и логи xray. |
| Прокси «недоступен» при добавлении | SOCKS5 с авторизацией Chromium не умеет — нужен `http://`. Проверьте логин/пароль и доступность порта. |
| Автовход: «кнопка входа осталась неактивной» | TikTok не принял данные формы. Чаще всего — опечатка в логине/пароле; пароль должен быть таким же, как вводите руками (латиница). |
| Автовход: «почта не подключена» | Задайте Client ID в «Настройках» и нажмите «Подключить почту» у профиля (см. п. 8а). |
| «Не задан Client ID приложения Microsoft» | Не выполнен разовый шаг с регистрацией приложения Azure — см. п. 8а. |
| Почта: «Microsoft отклонил токен» | Refresh-токен истёк (ящиком долго не пользовались) — нажмите «Подключить почту» заново. |
| Постинг падает на «не найдено поле загрузки» | TikTok сменил вёрстку или ограничил аккаунт — смотрите селекторы в `tiktok.py`. |
| ffmpeg/Playwright `false` в `/api/health` | Пересоберите бэкенд: `docker compose build --no-cache backend && docker compose up -d`. |

Полезное:

```bash
curl -s http://localhost:8088/api/health          # быстрая проверка
docker compose logs --tail 100 backend            # ошибки рендера/постинга
cat update/status; cat update/git_status           # что делает апдейтер
tail -50 update/updater.log                       # лог pull + пересборки
```

## 16. Что где лежит

```
video-poster/
├── backend/                 FastAPI, SQLAlchemy, APScheduler, ffmpeg, Playwright
│   └── app/services/        media.py (рендер), runner.py (очередь),
│                            telegram.py (бот), uploaders/ (TikTok, YouTube)

├── xray/config.example.json шаблон VLESS-конфига (свой — в config.json)
├── install.sh               установка: .env, сборка, автозапуск апдейтера
├── updater.sh               хостовый апдейтер (systemd vp-updater)
├── update/                  флаг/версия/статус обновления (в git не входит)
└── .env                     порт, логин/пароль, COMPOSE_FILE (в git не входит)
```

Данные — в docker-томе `vp_data` (внутри контейнера `/data`): `videos/`,
`banners/`, `cookies/`, `output/`, `video_poster.db`.
