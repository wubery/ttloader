# Установка Video Poster на сервер

Панель автопостинга в TikTok/YouTube Shorts в Docker. Панель закрыта входом
(логин/пароль, опционально — подтверждение через Telegram); защита на уровне приложения.

## Требования

- Linux-сервер с **Docker** и **docker compose** (плагин v2), **git**.
- Открытый порт панели (по умолчанию **8088**).

## Установка (рекомендуется — из git, чтобы работало самообновление)

```bash
git clone https://github.com/wubery/ttloader.git video-poster
cd video-poster
bash install.sh
```

Установщик соберёт контейнеры, настроит хостовый апдейтер (systemd `vp-updater`)
и **один раз** покажет в консоли логин/пароль:

```
Панель:  http://<IP-сервера>:8088
Логин:   admin
Пароль:  <случайный пароль>
```

Первая сборка — несколько минут (тянется образ Playwright ~2 ГБ и Chromium).

## Установка из архива (если прислали zip)

```bash
unzip video-poster-v2.zip      # появится папка video-poster/
cd video-poster
bash install.sh
```

Всё то же самое, только кнопка «Обновить с GitHub» в панели работать не будет
(для неё нужен git-клон — см. вариант выше).

**В архиве нет никаких секретов**: свои токен бота, chat_id и прокси вы задаёте
сами — токен и chat_id в панели («Настройки»), прокси у каждого аккаунта на
вкладке «Аккаунты». Логин и пароль для входа установщик сгенерирует при первом
запуске и покажет в консоли.

## Параметры установки

```bash
VP_PORT=9000 bash install.sh          # другой порт
VP_USER=boss bash install.sh          # другой логин
VP_PASS='МойПароль' bash install.sh   # задать свой пароль
VP_REGEN=1 bash install.sh            # пересоздать .env с новыми логином/паролем
```

Логин/пароль хранятся в `.env` (в git не попадает) и применяются при первом запуске.
Дальше пароль меняется в самой панели → вкладка **«Настройки»**.

## Вход и Telegram

- Вход в панель — логин/пароль на странице входа.
- В «Настройках» можно задать **токен бота** (@BotFather) и **chat_id**, включить
  **вход через Telegram** (панель пришлёт код в чат) и получать **уведомления**
  о постинге и упавших прокси. Бот-команды: `/queue`, `/accounts`; присланное боту
  видео добавляется в библиотеку.

## Telegram через туннель (если api.telegram.org заблокирован у провайдера)

Если сервер не может напрямую достучаться до Telegram, поднимите рядом xray-клиент
(VLESS → локальный HTTP-прокси). Через туннель идёт только трафик бота.

```bash
cp xray/config.example.json xray/config.json   # впишите свой VLESS (адрес/порт/uuid)
docker compose -f docker-compose.yml -f docker-compose.xray.yml up -d --build
```

Файл `xray/config.json` в git не попадает (там ваш uuid). Backend получит
`TELEGRAM_PROXY=http://xray:10809` автоматически из override-файла.

## Управление

```bash
cd video-poster
docker compose ps
docker compose logs -f backend
docker compose restart
docker compose down
```

## Обновление

- Из панели: «Настройки» → **«Обновить с GitHub»** (хостовый `vp-updater` сделает
  `git pull` + пересборку). Работает, только если проект **склонирован через git**.
- Вручную: `git pull && docker compose up -d --build`.

## Приватный репозиторий (доступ коллеге + обновления по токену)

### 1. Дать доступ коллеге

GitHub → репозиторий → **Settings → Collaborators → Add people** → его ник → роль
**Write** (или **Read**, если правки не нужны). Он получит приглашение на почту.

Раздел «Contributors» на GitHub руками не редактируется — он строится из истории
коммитов: человек появится там сам, когда его коммит попадёт в основную ветку.

### 2. Сделать репозиторий приватным

GitHub → **Settings → General → Danger Zone → Change repository visibility →
Make private**. Коллеги-collaborators доступ сохраняют, посторонние — теряют.

### 3. Токен, чтобы обновление продолжало работать

Пароль GitHub для git давно не принимает — нужен **токен**:

GitHub → **Settings → Developer settings → Personal access tokens →
Fine-grained tokens → Generate new token**:

- **Repository access**: Only select repositories → этот репозиторий;
- **Permissions → Repository permissions → Contents: Read-only** (больше не нужно);
- срок — на своё усмотрение (после истечения токен надо будет заменить).

Токен вида `github_pat_…` вписывается **в панели**: «Настройки» → «Обновление» →
«Токен для приватного репозитория». Кнопка «Обновить с GitHub» после этого работает
как раньше — логин/пароль панель не спрашивает.

Как это хранится: токен **не попадает в БД**. Панель передаёт его хостовому
апдейтеру через файл `update/git_token` (права 600), тот переносит токен в
`.git-credentials` (600, в `.gitignore`) и файл сразу удаляет. В `git remote -v`
и в логах токен не появляется.

Рядом с кнопкой обновления видно состояние доступа: «доступ к репозиторию есть» /
«нужен токен GitHub» / «установлено не из git».

### 4. Установка на сервер коллеги (репозиторий уже приватный)

```bash
git clone https://<ТОКЕН>@github.com/wubery/ttloader.git video-poster
cd video-poster
VP_GIT_TOKEN=<ТОКЕН> bash install.sh
```

`VP_GIT_TOKEN` сразу настроит доступ для обновлений (можно не задавать — тогда
вписать токен потом в панели). Токен из URL клона `install.sh` уберёт, чтобы он не
светился в `git remote -v`.

Альтернатива токену — **deploy key**: `ssh-keygen -t ed25519` на сервере, публичный
ключ в GitHub → Settings → **Deploy keys** (read-only), `git remote set-url origin
git@github.com:wubery/ttloader.git`. Ключ действует только на этот репозиторий и не
истекает по сроку.

## Важно

- Данные (аккаунты, куки, видео, БД) — в docker-томе `vp_data`, при обновлении сохраняются.
- Прокси и куки аккаунтов настраиваются в панели. Вход в аккаунт — логин/пароль +
  код с почты (через прокси аккаунта); при капче панель покажет скриншот, тогда войдите
  в антидетект-браузере через тот же прокси и импортируйте куки (кнопка «Импорт кук»).
- SOCKS5 с логином/паролем Chromium не поддерживает — используйте `http://`-прокси.
- Если прокси на том же VPS, что и панель, IP входа и постинга совпадут (это хорошо для TikTok).
